# Scripture Matching Engine

## 목적

사용자의 감정 단어 하나만 보고 성경본문을 선택하지 않는다.

다음 다섯 요소를 함께 고려한다.

1. situation
2. emotion
3. spiritualQuestion
4. prayerMode
5. pastoralFunction

안전과 misuseGuards는 점수와 별도의 차단 조건으로 사용한다.

## 처리 흐름

사용자의 '지금 나의 상황'

→ 상황 분석

→ 감정 분석

→ 말씀 앞의 핵심 신앙적 질문 분석

→ 기도 성격 분석

→ 안전 여부 확인

→ Scripture Card 후보 비교

→ 최종 카드 선택

## 점수

spiritualQuestionTags 일치:
최대 30점

situationTags 일치:
최대 25점

pastoralFunction 일치:
최대 20점

emotionTags 일치:
최대 15점

prayerModes 일치:
최대 10점

총점:
100점

중요:
단순 문자열이 완전히 같은 경우에만 의존하지 않도록
향후 OpenAI가 카드와 동일한 표준 태그를 반환하는 구조로 설계한다.

## 안전

다음 상황은 일반적인 점수 계산보다 먼저 처리한다.

- 자해
- 자살 의도
- 타인에 대한 폭력 의도
- 진행 중인 학대나 폭력
- 즉각적인 신체 위험
- 긴급 의료 상황

이 경우 일반적인 말씀 추천과 기도문 제공보다
현실적인 안전 안내를 우선한다.

## 본문 오용

misuseGuards는 추천 점수가 아니다.

선택된 카드가 현재 사용자 상황에 위험하게 적용될 가능성이 있는지
최종 검수하는 안전장치다.

예:
학대 상황에서
'참으라', '용서하라', '순종하라'는 방향으로 사용자를 위험에 머물게 하지 않는다.

## 낮은 확신과 추가 질문

첫 입력만으로 영역과 말씀이 정해지면 추가 질문 없이 바로 추천한다.

두 영역이 함께 보여 중심 영역을 정하기 어려운 `domain_choice`와,
영역은 정해졌지만 여러 말씀이 동점인 `ambiguous`에서 사용자가 상황을 자연스럽게 더 말할 수 있는
질문을 한 번에 하나씩 보여준다. 질문은 핵심 어려움 구분 → 구체적인 장면과 마음 → 현재 영향과
바라는 도움 순서이며, 판단·진단하거나 답을 유도하지 않는다. `domain_choice`에서는 질문에 답하지
않고 두 영역 중 하나를 바로 고를 수도 있다.

추가 설명은 기존 추천 절차로 다시 분석하고, 매 단계에서 말씀이 정해지면 즉시 끝낸다.
두 경로를 오가더라도 추가 질문은 합계 최대 3번이다. 그 뒤에도 범위가 넓으면 계속 질문하지 않는다.
`domain_choice`는 두 영역을 직접 고르게 하고, `ambiguous`는 한 말씀을 임의로 고르지 않은 채 멈춘다.
안전 신호는 추가 질문보다 우선해 기존 안전 안내로 바로 보낸다.

따라서 매칭 확신이 낮더라도 임의의 본문을 자신 있게 추천하지 않는다.

향후 카드 수가 충분해졌을 때
fallback card 또는 low-confidence 처리 규칙을 별도로 추가한다.

현재 카드만으로 모든 상황을 커버한다고 가정하지 않는다.

## 구현 메모 (2026-08-27 기준)

이 아래는 위 규칙을 코드로 어디까지 옮겼는지에 대한 기록이다. 규칙 자체가 아니라 현재 상태를 남긴다.

### 지금 구현된 것

- `src/lib/scripture-matcher.ts`: 이미 구조화된 태그 입력을 받아 Scripture Card 10개와 비교하고 점수를 매긴다.
- `src/lib/scripture-matcher.test.ts`: 8개 표준 상황에 대한 코드 테스트. `npm test`로 실행한다.

### 아직 구현하지 않은 것

- 사용자의 자유문장을 분석해 태그로 바꾸는 단계 (OpenAI 연결 예정)
- 안전 확인 단계
- misuseGuards 최종 검수 단계
- 낮은 확신 처리와 fallback card
- 앱 화면 연결 (두 번째 화면은 아직 SC-001로 고정되어 있다)

### 점수 계산 방식

각 요소마다 다음과 같이 계산한다.

```
요소 점수 = 요소 최대 점수 × (입력 태그 중 카드와 일치한 개수 ÷ 입력 태그 개수)
```

- 입력에 없는 요소는 0점으로 두고, 그 요소 때문에 카드가 불리해지지 않는다.
- 카드에만 있고 입력에 없는 태그는 감점하지 않는다.
- 태그 비교는 정확히 같은 문자열일 때만 일치로 본다. 앞으로 OpenAI가 카드와 같은 표준 태그를 돌려주게 만들어 이 방식이 유지되도록 한다.
- 결과는 모든 카드의 점수를 정렬해 돌려주며, 최고 점수가 여러 장이면 동점 카드를 모두 함께 돌려준다. 동점을 임의로 하나만 고르지 않는다.
